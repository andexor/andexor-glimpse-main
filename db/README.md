# Andexor Glimpse — database schemas

Three kinds of Cloudflare D1 database, none shared, none replicated. Each has exactly one owning Worker.

| Folder | Database | Owning Worker | Purpose |
| --- | --- | --- | --- |
| `system/` | `andexor-glimpse-admin-api` | `admin-api` | System of record: prospects, glimpse lifecycle, scheduled jobs, provisioning runs, notifications sent by admin-api |
| `portal/` | `andexor-glimpse-portal-api` | `portal-api` | Prospect-facing: glimpse record, append-only `decision_log` (APPROVED / DECLINED / DELAYED), comments, notifications sent by portal-api |
| `glimpse/` | `andexor-glimpse-<id>-api` | that glimpse's API | `meta` only until a real design adds tables |

## Migration convention

- Files are `NNNN_short_name.sql`, four-digit zero-padded, applied in order. `0001_init.sql` is the baseline.
- Every migration is idempotent-safe to re-run only through the `schema_migration` table: the migration runner checks `version` before applying and inserts its row inside the same transaction.
- Migrations are the only path that runs DDL. They execute from the `-api` repo's deploy workflow using the `glimpse-d1-edit-token` from Secrets Store (the `admin` role in PRD 7a). Runtime code never issues `CREATE`, `ALTER`, or `DROP`.
- D1 runs SQLite; `PRAGMA foreign_keys = ON` is per-connection and is set by the data-access layer on every request as well as at the top of each migration.
- Timestamps are ISO-8601 UTC text. Identifiers generated by the system are lowercase.

## System Reference Table (SRT)

Every database has an `srt` table: `(domain, code, label, description, sort_order, active)`, primary key `(domain, code)`. It is the authoritative list of every finite-value code in that database, and codes are **UPPERCASE** without exception. Each column that holds such a code has a pair of triggers (`srt_<table>_<column>_ins` / `_upd`, generated by `tools/gen_srt_triggers.py`) that reject any value not present and active in `srt`. Adding or retiring a value is therefore a migration that touches `srt`, never a code edit.

| Database | Domains |
| --- | --- |
| system | `GLIMPSE_STATE` (PROVISIONING, FAILED, DRAFT, PENDING, APPROVED, DECLINED, DELAYED, EXPIRED, DELETED), `ACTOR`, `JOB_KIND`, `JOB_STATUS`, `RUN_KIND`, `RUN_STATUS`, `STEP_STATUS`, `RECIPIENT`, `CHANNEL`, `NOTIFICATION_STATUS` |
| portal | `DECISION_ACTION` (APPROVED, DECLINED, DELAYED), `AUTHOR`, `RECIPIENT`, `CHANNEL`, `NOTIFICATION_STATUS` |
| glimpse | empty at creation; a real design registers its own |

UIs read labels and sort order from `srt` rather than hard-coding them; the APIs expose `srt` read-only for that purpose.

## Access roles (PRD 7a)

| Role | Statements | Held by |
| --- | --- | --- |
| `reader` | `SELECT` | portal-api reads; Ed's inspection token (`glimpse-d1-read-token`) |
| `writer` | `reader` + `INSERT` / `UPDATE` / `DELETE` on rows | each API on its own database at runtime |
| `admin` | `writer` + DDL, database create/delete, export, Time Travel | admin-api provisioning; migration step in CI |

D1 has no users or grants; these roles are enforced by binding scope (one Worker per database), by a role-split data-access module per API with a statement allow-list, and by which token a process holds.

## Cross-database contract

- `prospect.id` and `glimpse.id` carry the same values in the system and portal databases; admin-api is the source and writes them to portal-api (`upsert_glimpse`) at notify / reactivate / extend / expire / delete.
- portal-api reports each APPROVED/DECLINED to admin-api (`record_decision`) and each DELAYED via `extend`; admin-api stores only the resulting `glimpse.state`, never the log.
- `glimpse.extension_count` and `last_extended_at` in the system database are updated by admin-api on `extend`; they are a counter, not a copy of `decision_log`.
- One hostname per glimpse: the UI Worker serves `<id>.glimpse.andexor.net/*` and the API Worker `<id>.glimpse.andexor.net/api/*` (two Routes, one Access application). Admin and portal tiers follow the same pattern.
- Nothing in a glimpse database references either of the others.
